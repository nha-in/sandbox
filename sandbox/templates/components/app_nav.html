{% comment %} Sidebar navigation, shared by the desktop rail and the mobile drawer so the two cannot drift apart. Context: nav_section — slug of the active section, set by each view. nav_counts — optional {section_slug: int}. Resolved in the view, never here: a query per badge would put one per sidebar per request. Only screens that exist are listed. The mockups show Milestones, Conformance, Reference environment, Agent Skills, Support and a public directory; none of them has a backend in v0, and a nav link to a screen that does not exist is a defect this repo has already shipped twice (the wizard and the org switcher were both unreachable while fully tested). They arrive when their pages do. The membership branch matters as much as the list. Every link in it goes through OrganisationMixin, which answers a non-member with a 404 — so for someone who has just signed up the whole rail would be dead ends. Staff are non-members by design and are not invited to create one. Boosted per 02-ui.md §3.2: htmx fetches the very URL each href already points at, keeps #main-content out of the whole-page response, and picks this nav out of the same response out-of-band so the active item follows the page. With JavaScript off every link below is a plain and the browser navigates normally — the path that has to keep working. Each link carries an id because the out-of-band swap destroys the anchor that was activated; htmx restores focus to the element with the same id, and without one a keyboard user is dropped at the top of the document. {% endcomment %} {% load i18n %}
